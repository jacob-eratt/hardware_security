## Goal (from the user)

The policy is unknown on real hardware; fixed policies are only baselines and simulated test targets.

## What was done today

1. **Hardware, Celeron L2** (W = 16, 2 MiB huge pages). Raised `hw.repeats` to 64 (`hardware_security_project/configs/hw_l2_celeron.yaml`) and regenerated 100k train and 8k independent test streams.
   - The plain GRU (`cpl.train_hits`) scores **0.9706** on the independent test (run `cache-policy-learning/runs/hit_celeron_v2`).
   - The label ceiling is about 0.997, so the remaining gap is the model's, not label noise. That motivated the structured model.
2. **Three-unit "slot" model** (`cache-policy-learning/src/cpl/model/slot_cache.py`). It has exact residency, per-way GRU states with shared weights, a global state, way identities and a used-way broadcast. It is trained by hindsight (`cpl/train_hindsight.py`): hit/miss labels give the allowed victims, with EDF feasibility, a partial-label loss and fading Gumbel exploration.
3. **Back to basics on a perfect simulator**, at the user's request:
   - `hardware_security_project/src/cpl/data/sim_stream_dataset.py` generates streams with full ground truth: victims, filled way, contents and policy state.
   - `cache-policy-learning/src/cpl/eval_sim.py` is the grader. It reports hit/miss, reuse-distance buckets, exact-stream, contents accuracy and contents exact-stream, plus baselines. On tree-PLRU data an independent tree-PLRU predictor must score 1.0, which checks the grader itself.
   - `cache-policy-learning/src/cpl/analyze_sim.py` runs on val only. It gives decision accuracy from the same state and, for tree-PLRU, the tree level of each first error.
4. **Tree-PLRU comparison:**
   - plain GRU: 0.9407 (exact-stream 0.114);
   - slot model with hindsight and no ages: 0.9854 (contents exact-stream 0.637).
5. **Capacity tests with true victim labels.** The model learns tree-PLRU exactly both without and with line ages (A and B), so representation was not the limit.
6. **Recipe C, the current one:** hit/miss-only hindsight training, plus **fill-order naming** (empty ways filled lowest-index first) and **line ages** (each way's recency and insertion rank plus the whole set's vectors). Tree-PLRU: acc 1.0000, contents exact-stream 0.998. It reproduces over 3 seeds.

**Caveats to keep in mind:**
- LRU and FIFO are near-trivial once ages are given: the answer is the oldest rank.
- Hit/miss accuracy hides wrong evictions that rarely matter later. Contents exact-stream is the honest headline metric.

## Reproduce

Datasets are **not committed**, so regenerate them first. Run from `hardware_security_project` with `PYTHONPATH=src` and the `cache-policy-learning` venv's python:

```bash
for p in plru lru fifo bitplru srrip; do
  python -m cpl.data.sim_stream_dataset --policy $p --W 16 --pool 24 --n 100000 --len-min 32 --len-max 96 \
      --seed 1 --val-frac 0.05 --out data/processed/sim_${p}_stream
  python -m cpl.data.sim_stream_dataset --policy $p --W 16 --pool 24 --n 8000 --len-min 32 --len-max 96 \
      --seed 2 --all-test --out data/processed/sim_${p}_stream_test
done
```

Train and grade with recipe C, from `cache-policy-learning` with `PYTHONPATH=src`. Each run takes about 60–85 minutes on a laptop CPU; we ran 4 at once with 3 torch threads each.

```bash
D=../hardware_security_project/data/processed; p=srrip
python -m cpl.train_hindsight --data-dir $D/sim_${p}_stream --test-dir $D/sim_${p}_stream_test \
    --use-ages --epochs 15 --seed 1234 --run-dir runs/sim_${p}_capC > runs/sim_${p}_capC.log 2>&1
python -m cpl.eval_sim --test-dir $D/sim_${p}_stream_test --slot runs/sim_${p}_capC/best.pt --out runs/sim_${p}_capC_eval.json
python -m cpl.analyze_sim --data-dir $D/sim_${p}_stream --slot runs/sim_${p}_capC/best.pt   # val split only
```

To train the plain-GRU baseline: `python -m cpl.train_hits --data-dir $D/sim_${p}_stream --test-dir $D/sim_${p}_stream_test --hidden 256 --layers 2 --epochs 25 --device cpu --run-dir runs/sim_${p}_gru`, then grade it with `eval_sim --gru`.

To run the tests, from `hardware_security_project`: `PYTHONPATH=src ../cache-policy-learning/.venv/bin/python -m pytest -q tests` (155 pass).

## Hardware access (Celeron)

- **Access:** `ssh celeron` (a host alias in the user's SSH config).
- **Sudo:** a passwordless rule in `/etc/sudoers.d/hwcache` allows only the venv python, `tee` and `chown`. sudo strips `PYTHONPATH`, so run modules via `python -c "import sys,runpy; sys.path.insert(0,'src'); runpy.run_module('cpl.data.hw_stream_dataset', run_name='__main__')" ...`.
- **Still active from today's measurements:**
  - cpu1 is offline (it is the L2 sibling of the pinned core);
  - the governor is set to `performance`;
  - 256 huge pages are reserved.
  
  Restore these when hardware work is finished. Remove the sudoers rule (`sudo rm /etc/sudoers.d/hwcache`) only when the user says so.
- **Killing jobs:** never `pkill -f` over ssh, because the pattern matches the ssh command itself and kills your own session. Kill by PID.
- **Which i7:** `configs/hw_l2_i7.yaml` and the Windows large-page commits (99c94c3, 1fa2253) are for a different i7, not the Ubuntu target.
